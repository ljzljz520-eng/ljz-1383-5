# 咖啡师履历与课程站

Web 展示拉花作品、比赛经历与学习阶段；管理端编辑门店与课程；后台数据库连接成长证据、素材与预约。

## 运行

```bash
npm install
npm start          # http://localhost:3000 （首次启动自动写入演示数据并发布 v1）
npm test           # 12 项验收测试
npm run seed       # 重置后手动播种（删除 data/ 可重置）
```

## 架构

```
src/
  db.js                 SQLite（WAL + 外键），schema 与兼容版本号
  format.js             UTC → IANA 时区格式化（跨时区展示）
  services/
    capacity.js         容量：固定班级容量 vs 资源瓶颈动态计算 + 冲突解释
    booking.js          预约事务：临时占位 / 确认绑定快照 / 候补晋升 / 取消释放
    sessions.js         排课（讲师重叠校验、资源校验）与撤课
    shops.js            改址：bump 地址版本 + 标记待学员确认
    publishing.js       发布版本：公开年表与课程页只读「兼容」版本
  routes/               public（公开页）/ admin（管理端）/ api（JSON）
  views.js              服务端渲染（照片失败保留文字、浏览器时区换算）
test/acceptance.test.js 验收测试
```

## 关键设计决策

- **调店不改写旧作品**：`works.shop_id` 是出品时快照；任职有有效区间
  （`employments.started_on/ended_on`），年表据此核实作品归属。
- **比赛经历**：`competitions.role`（选手/评委/教练）+ `event_date`，逐条关联。
- **课程占用三类资源**：讲师（排他）+ 工位 + 机器。动态容量 =
  `min(空闲工位, 空闲机器)`，空闲量扣除本课演示占用与重叠课次占用；
  管理界面并列展示固定容量与动态瓶颈值，并解释容量来源与冲突（超售风险、
  讲师重叠、资源耗尽）。
- **候补 / 临时占位 / 取消释放**：占位（held）有有效期，过期清扫自动顺延候补；
  取消立即释放并晋升最早候补为新占位。所有「检查+写入」在单事务内完成，
  最后一个工位并发预订只有一人成功。
- **预约确认绑定快照**：确认时写入当时课程内容（含版本）与门店地址（含地址版本）。
  门店改址只 bump `address_version` 并把受影响预约标记 `reconfirm_required`，
  学员页面同时展示旧快照与新地址、待学员再确认——不会只更新页面地图。
- **撤课与确认竞争**：确认事务内重查课次状态；撤课后确认失败并释放占位。
- **公开照片失败保留文字**：授权到期服务端不渲染 `<img>`；加载失败客户端
  `onerror` 替换为文字卡片。
- **发布版本**：公开年表/课程页读取最新**兼容**发布版本，不兼容版本自动回退；
  管理端未发布的修改不影响公开页。
- **豆单**：个人记录；未经核对的品质结论一律带「未经核对，非认证事实」标注，
  不作为认证事实展示。

## 验收场景 → 测试映射（test/acceptance.test.js）

| 验收项 | 测试 |
| --- | --- |
| 最后一个工位被并发预订 | #1 并发占位仅一人成功，其余候补 |
| 讲师排期重叠 | #2 409 + 冲突明细；边界相接允许 |
| 课程跨时区展示 | #3 UTC 存储，门店/浏览者时区各自正确 |
| 作品授权到期 | #4 不渲染图片、保留文字；破损照片有兜底 |
| 撤课时学员正在确认 | #5 确认 410、占位释放、撤课后不可再约 |
| 候补/占位/取消释放 | #6 释放晋升候补、过期清扫顺延 |
| 改址待学员确认 | #7 快照不静默覆盖，再确认后更新 |
| 兼容发布版本读取 | #8 不兼容版本回退、未发布修改不可见 |
| 调店旧作品归属 | #9 旧作品仍属旧门店 |
| 容量来源解释 | #10 固定 vs 动态对比、超售风险提示 |
| 豆单免责 | #11 未核对结论不作认证事实 |
| 比赛角色日期 / 任职区间 | #12 年表展示 |
